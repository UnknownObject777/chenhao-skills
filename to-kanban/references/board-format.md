# Obsidian 个人规划看板格式

只有本周期诉求和主要矛盾都确认后，才使用本文件生成看板。

## 文件与链接

优先沿用用户给定目录；没有约定时建议以下相对 vault 根目录的结构，不能把它当成已存在的路径：

```text
规划/月/2026-09.md
规划/周/2026-09-01_2026-09-07.md
规划/日/2026-09-01.md
```

示例周是用户指定的连续七天，不强行改为自然周。月份及日期必须来自当前已确认的周期。创建文件时避免覆盖同名笔记；已存在则先读内容，再按授权更新。

每张卡用稳定的 ASCII 块 ID，如 `^m-202609-01`、`^w-20260901-01`、`^d-20260901-01`。已有卡不重新编号。跨文件引用用 `[[规划/月/2026-09#^m-202609-01]]`。目标必须实际存在或在同一批交付中创建；否则写“上级未建立”。

主线月卡、周卡和日卡互链，但不复制成三份可累计工时的行动。子卡引用上级；上级卡以“下级”链接指回子卡。只有在用户授权修改相应上级文件时才补反向链接，否则说明待补。

## 属性与列

文件以 `kanban-plugin: board` 的 YAML 属性开头。属性至少保留：周期、起始日期、结束日期、主要诉求、主要矛盾、判断依据、次要矛盾及反向验证、先动哪里、确认状态、上级看板。

已知容量时另存可用分钟、计划分钟、缓冲分钟。未知时写“未知”或“待估时”，不能写 0 或编一个工作日长度。中文字符串、链接及含冒号的值加引号。月/周总投入只汇总一次，不能再叠加每日明细。

使用以下五列：

| 列 | 意义 |
|---|---|
| 候选与暂缓 | 尚未承诺、待估时、推迟或取消的事项；取消明确写原因，保持未勾选 |
| 待办 | 本周期已纳入容量的任务 |
| 进行中 | 用户实际已经开始的任务，不能仅凭排程自动移动 |
| 等待 | 明确被外部条件或依赖阻塞的任务，标出等什么 |
| 完成 | 用户确认或有实际证据达到完成标准的任务 |

`##` 标题只用于这些列。说明、诉求和复盘信息放 YAML 属性或卡片内，不另造“主要矛盾”等伪任务列。

## 卡片

每张卡为一条 `- [ ]` 或 `- [x]` 列表项。默认单行，以 `；` 分隔短字段，复杂材料链接到笔记，不使用嵌套勾选清单表示卡片字段。

字段顺序：领域、动作或成果、类型、预计用时、完成标准、上级、可选依赖/下级/来源/日期、块 ID。类型分为主线、必要事务、生活维持。没有真实依赖或日期时省略对应字段。

- 日卡预计用时必填，未知写待估时并放候选列。
- 月卡、周卡是成果，不强求一天做完；投入可标估算或待估时。
- 必要事务和生活维持可以写“上级：独立事项”，不杜撰科研关联。
- 截止只写真实外部约束；建议执行日期另标“建议安排”。

## 示例：已确认的日计划

这是格式示例，不是用户的真实计划。假设用户确认：9 月 1 日先解决方法写作卡住的问题；扣除固定安排后有 120 分钟，其中预留 30 分钟；周卡 `w-20260901-01` 已存在。论文与一个必须提交的报销事项均在范围内。

````markdown
---
kanban-plugin: board
周期: "日"
起始日期: "2026-09-01"
结束日期: "2026-09-01"
主要诉求: "推进方法初稿，并完成到期报销"
主要矛盾: "需要写出可读的方法说明 ↔ 核心步骤尚未组织清楚"
判断依据:
  - "用户确认写作卡在组织方法步骤；理清步骤决定能否起草正文"
  - "结构理清后，写作顺序和表述困难会降级"
次要矛盾及反向验证:
  - "想直接写正文 ↔ 不知道从哪段开始：结构明确后降级"
  - "需要解释方法 ↔ 步骤之间关系不清：结构明确后降级"
  - "报销今天截止 ↔ 尚未提交：照旧，作为独立必要事务保留"
先动哪里: "先把核心步骤组织成可写作的提纲"
确认状态: "已确认"
上级看板:
  - "[[规划/周/2026-09-01_2026-09-07]]"
可用分钟: 120
计划分钟: 90
缓冲分钟: 30
---

## 候选与暂缓

## 待办

- [ ] [科研] 写出方法步骤提纲；类型：主线；预计：60 分钟，估算；完成，当：输入、核心步骤、输出及步骤关系都写清；上级：[[规划/周/2026-09-01_2026-09-07#^w-20260901-01]] ^d-20260901-01
- [ ] [生活] 提交已齐全的报销材料；类型：必要事务；预计：30 分钟，估算；完成，当：提交成功并保存回执；上级：独立事项；截止：2026-09-01 ^d-20260901-02

## 进行中

## 等待

## 完成

%% kanban:settings
```
{"kanban-plugin":"board","show-checkboxes":true,"list-collapse":[false,false,false,false,false]}
```
%%
````

`list-collapse` 长度与列数一致。用户已有其他设置时保留，不重置整个设置对象。Markdown 普通阅读也应能看懂，不依赖插件专属图标来表达状态。

## 创作卡片与画布

默认交付仍是 Markdown 看板。若用户另外请求 Canvas，可将已有的月、周、日笔记作为文件卡片连接，表达目标与行动的关系；不复制一套独立任务状态，也不默认创建 `.canvas` 文件。

长期创作素材可独立保存为 Markdown 笔记，再链接到任务卡或 Canvas。Bases 卡片视图、Excalidraw 及其他插件均是可选呈现工具，不是本技能的运行依赖。推荐插件时核实当前官方资料；插件未装时不声称已在 Obsidian 中渲染验证。
