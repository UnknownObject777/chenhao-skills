# 踩坑清单

> 全部来自真实事故，不是设想。每条给出现象、根因、对策。
> 方法论主文档见 `METHODOLOGY.md`。

---

## 一、幻觉相关

### 1. 静默删行

**现象**：引用一段文档注释时悄悄删掉六行，删掉的恰好是「有意保留什么」那半段，正文结论因此不完整，但表面看不出破绽。

**根因**：为了让代码块短一点。

**对策**：省略必须写成含 `...` 的整行注释。逐字节校验器会把引用块按省略标记切成连续段，任何一段拼不上就判 FABRICATION。

### 2. 抄错一个符号

**现象**：`SIGSYS_CODE` 抄成 `SIGSYS`、`unsafe { f() };` 抄成 `unsafe { f(); }`、漏掉函数上方的 `#[test]`。

**根因**：手打，没有复制粘贴。

**对策**：贴代码一律复制粘贴。这类错误人眼几乎看不出来，只有逐字节校验能抓。

### 3. 照抄大纲里的候选行号

**现象**：正文行号指向的位置不是要讲的那段代码。

**根因**：把大纲当成已核实的事实。

**对策**：大纲里标 ✓ 的含义是「曾经核实过」，不是「现在还对」。即使标了 ✓ 也要重新实读，因为真正要引用的可能是相邻的行。

### 4. 行数统计 off-by-one

**现象**：README 报 239 行实际 238 行，`migrations.rs` 报 122 行实际 121 行。

**根因**：末行有无换行符导致不同工具口径不同。

**对策**：统一用 `splitlines()` 作为口径，并在规范里写明。

### 5. 引用符号链接

**现象**：同一条不变量在一门课里引 `CLAUDE.md` 第 107 行，在另一门课里引 `AGENTS.md` 第 107 行，看起来自相矛盾。

**根因**：`CLAUDE.md` 是指向 `AGENTS.md` 的符号链接，两处都不算错。

**对策**：引真实文件，并在正文里注明符号链接关系。

### 6. 把注释当成代码行为陈述

**现象**：正文说「源码会先检查 X」，实际那只是注释里的一句说明，代码没有这个检查。

**对策**：引用注释时明确说这是注释。

## 二、校验器相关

### 7. 校验器建得太晚

**现象**：批量生产完才发现大面积行号漂移，返工成本极高。

**对策**：校验器必须在批量生产之前建好，并且跑通至少一章。

### 8. 只校验「现有引用是否正确」

**现象**：某章初稿 56 处引用带若干报错，交付时只剩 22 处、全部通过。作者把报错的引用删掉了。

**根因**：校验器不报「该有的引用是否还在」，删引用就能变绿。

**对策**：加引用密度下限检查。交付前后对比引用数量，显著下降要人工复核。

### 9. 校验器误报导致被忽略

**现象**：四个真实误报，把闭合花括号判成内容不符、把正文里合理的中文引号判成违规、把品牌图标的 SVG 路径判成缺 `fill="none"`、把自动生成的 SEO 区块判成手写注入。

**根因**：校验规则没有区分上下文。

**对策**：每修一个误报都记下判据（为什么这种情况不算违规），不然下一次重构会把它改回去。误报会让人开始忽略输出，那等于没有校验。

### 10. 省略标记判得太宽，在校验里凿了个洞

**现象**：一处引用声明 `123:127`，实际内容从源文件 121 行的文档注释开始，校验器却报「行号需校正 0 处」。

**根因**：省略标记的判据写成了「整行是注释且含 `...`」。源码里 `/// Returns ... within a \`bash -lc "..."\` or` 这种正常的文档注释被当成了省略标记，于是这几行既不参与逐字节比对，也不参与行号推算。判据宽一分，校验盲区就大一片：落在这类行里的内容可以随便编，校验器不看。

**对策**：判据收紧成「整行是注释，且注释符号后面紧接着就是 `...`」。

```
    // ... 填 SID 表 ...          ← 是省略标记
    // 处理 bash -lc "..." 的情况    ← 不是，这是正常注释
```

真正的省略标记，`...` 一定紧跟在注释符号后面，收紧不会误伤。有人写成 `// 省略中间的 SID 表 ...` 会被当成正常代码去比对，然后报错，正好逼着统一到标准写法。

再加一条兜底：**没有省略标记、但行数和声明的区间对不上，就告警。** 这条能把引用头部起止行写错的情况直接兜出来。

### 11. 逐字节校验验证不了路径

**现象**：引用内容确实存在于某个文件，但正文写的路径是另一个文件。

**根因**：以内容为准的匹配会在所有语料仓库里搜，找到就算过。

**对策**：单独一个脚本查「被引用文件是否存在」「行号是否落在文件范围内」。

## 三、并行子 Agent 相关

### 12. 把检查糊弄过去

**现象**：页面渐入动画检查不过，子 Agent 就静态写死动画完成态、或加定时器强制显示，把检查骗过去。

**对策**：校验器加反作弊项，直接检测这些绕过手法。

### 13. 滥用省略标记凑字数

**现象**：某章出现 25 处省略标记，参照章是 0 处。

**根因**：把字数上限当成硬约束，靠省略压缩代码块。

**对策**：校验器统计省略密度并告警。规范里写明省略只用于确实无关的样板代码。字数是下限不是目标。

### 14. 误报上游文档写错

**现象**：子 Agent 报 9 处「大纲/课页写错了」，逐条核实只有 2 处成立。

**对策**：要求上报时带证据，格式固定为：被质疑的原话 → 源码文件与行号 → 那几行的原文 → 为什么对不上。并提前告知三种常见误判：

- 引用区间含文档注释、或末尾没收进 `}`，都不算错
- 顺着继承和别名再查一层再下结论。曾有人报「这几行里没有 `UNKNOWN_TOOL`」，实际是那行抛的异常在类定义处就带着 `code: 'UNKNOWN_TOOL'`
- 约数按约数判。文件 298 行，原文写「约 300 行」，成立

### 15. 给子 Agent 的前提是错的

**现象**：告诉子 Agent「对比语料不在本地」，导致它们绕开对比、改用引用旧课页的方式，对比章节质量下降。实际语料一直都在。

**对策**：派活前确认所有路径真实存在，不要凭印象说。

### 16. 边收边改上游文档

**现象**：并行生产中陆续收到大纲问题，改到一半又来一条，容易互相覆盖。

**对策**：开一个 `PENDING_FIXES.md` 累积，全部回来后统一核实统一修。

### 17. 并发写同一个文件

**现象**：多个子 Agent 同时往一份清单文件里追加条目，互相覆盖。

**对策**：每个子 Agent 写自己的分片文件，主流程合并后统一执行。

## 四、产出物与集成相关

### 18. 新内容没接进站点数据结构

**现象**：课页文件都生成了，但网站上看不到，目录里也没有。

**根因**：站点的课程目录、导航顺序、首页卡片是各自独立的数据源，生成文件只是第一步。

**对策**：把「接入清单」写进流程：课程目录数据、导航顺序、首页入口、统计数字、站点地图。能用脚本从课页反向生成的就别手写。

### 19. 计数口径不一致

**现象**：首页两个相邻数字一个含小结课一个不含，差 12，肉眼可见矛盾。静态兜底数字与 JS 现算值不一致，爬虫和真人看到的不一样。

**对策**：同一个数只算一次，多处共用。口径决定写进注释，测试锁住口径，改口径时测试和静态兜底一起改。

### 20. 同一天二次发布撞缓存戳

**现象**：数据文件内容从 7 课变成 32 课，但缓存戳没变，浏览器继续用早上缓存的旧版本，用户看到的还是旧目录。

**根因**：缓存戳按日期生成，同一天第二次发布时脚本报「改写 0 个页面」，容易被读成「无需处理」。

**对策**：报「改写 0 个」时要判断是「本来就是最新」还是「戳撞车了」。同日二次发布必须换字母后缀。

### 21. 变量提升导致填充静默失效

**现象**：证书文案永远显示占位词「全部」，数字始终没填进去。

**根因**：`var LESSON_TOTAL` 在下方赋值，上方读到的是 `undefined`，被 `if` 挡掉，无报错。

**对策**：这类静默失效只能靠真实浏览器验收发现。关键文案的最终渲染值要进验收清单。

### 22. 死代码等着一个不存在的元素

**现象**：一段脚本给所有带某属性的元素填数字，但页面里没有任何元素带这个属性。

**根因**：重构改了填充机制，旧机制的代码留着、新机制没有落地目标。

**对策**：测试断言「该属性至少存在一个元素」，让死代码暴露出来。

### 23. 全量重建导致新鲜度信号失真

**现象**：每次 SEO 重建改写全部页面，下一次按提交历史算日期时，所有页面的修改日期都成了当天。发布 diff 也永远是几百个文件。

**对策**：注入类脚本在内容没变时不要重写文件。

## 五、内容质量相关

### 24. 边界条件答成「看情况」

**对策**：必须落到源码里某个分支的具体行号。这一段是拉开深度的关键，含糊回答等于没写。

### 25. 对比写成功能清单对照

**现象**：「A 有这个功能，B 没有」。

**对策**：要写清 B 为什么可以没有、或者 B 用什么别的东西补上了。落到「同一个问题的两种答案」和各自的代价。

### 26. 演示设计写成一句话

**现象**：「做个动画演示这个流程」。

**对策**：必须分步、必须有每步的字幕文案、必须有逻辑轨迹面板。

### 27. 可迁移结论全都依赖某个语言

**现象**：结论全是 Rust 类型系统才能做到的事，用其他语言的读者带不走。

**对策**：至少一条结论不依赖该语言，并给出最小落地形态。

### 28. 互链硬凑

**现象**：为了让每张对比卡都有链接，指向只顺带提了一句的页面。

**对策**：唯一标准是读者点过去能看到这个机制的展开讲解。宁缺毋滥。结论是「没有对位实现」的卡片不要挂链接。同一页两张相邻卡片不要指向同一目标。

### 29. 正文泄露写作过程

**现象**：正文出现「大纲写…」「按规范要求」「本次任务」「我负责的这一章」，以及本机绝对路径。

**根因**：写作者忘记读者没见过大纲和规范。

**对策**：写进文风禁忌，用正则扫描。要表达「和流传说法不同」，写成「一个流传很广的说法是…，实际检索下来…」。
