## 1. 页面骨架

以样板页为模板，改标题、描述与正文。`<head>` 顺序固定：

```html
<meta charset> → viewport → title → 首屏淡入 style → <站点样式> → 页面私有 style → description → author
```

结尾脚本顺序固定：`<i18n>` → `<lesson>` → 页面演示脚本 → `<nav-inject>`。

**禁止手写** SEO / JSON-LD / paywall 区块，由构建脚本统一注入。手写会和自动注入打架，也会让检查脚本误报。

## 2. 视觉约束

本专题主色是 <色名>。页面私有 `<style>` 第一行必须原样照抄：

```css
/* 变量挂在 .lesson 上：导航脚本会在页面样式之后再注入一次 :root 主色，
   靠就近继承才能保住专题色。 */
:root,.lesson{--accent:<HEX>;--accent-deep:<HEX>;--accent-soft:<RGBA>}
```

**只写 `:root` 会被导航脚本顶掉**，页面会变回站点默认色。这是硬性要求，也是一个真实踩过的坑：CSS 里同名变量后写的胜出，必须靠更具体的选择器赢回来。

其余约束：

- 颜色只用站点样式的变量加上面三个主色变量，不引入新色板
- **全浅色，禁止深色背景**。演示区、结构图一律白底或米白底。深色只允许出现在 ≤50px 的小色块上
- 颜色留给语义：危险用 `--danger`，成功用 `--success`，其余一律主色。不要为了好看而上色
- **禁止 `border-left` / `border-top` 单边强调线**。强调用整卡浅色底、图标或加粗文字
- **图标只允许内联 SVG 线条风格，禁止 emoji**
- 所有正文区块加 `class="reveal"`，写窄屏 media query 收尾单列

### 排版松弛（硬性数值）

- 正文段落 `font-size:15px;line-height:2`，段间距 `margin:0 0 20px`
- 分节标题上方留白 ≥56px
- 卡片 padding ≥24px，网格 gap ≥20px，卡片内文字 `font-size:14px;line-height:1.9`
- **少用三列网格**，概念卡最多两列，一屏内不挤超过两个信息区块
- 列表每点独立成块，禁止用 `<br>` 把多点挤进一个段落
- SVG 结构图四周留白 ≥20px，节点文字 ≥13px
- **SVG 的 `<path>` 与 `<polyline>` 必须显式写 `fill="none"`**。SVG 默认 fill 是黑色，弯折路径会被填成黑块。只有箭头三角这类故意填充的才写具体颜色

## 3. 正文区块（按顺序）

1. **课程目标卡**：一段话说清读完能懂什么
2. **交互演示**，紧跟目标卡。读者先玩明白，再往下看思路
3. **设计思路**，正文重心。提炼 2 到 3 个思路，每个一小节，用固定三问展开：
   - 它解决什么问题：不这么做会出什么事，给一个具体的翻车场景
   - 思路是什么：用白话和一张浅色 SVG 图讲透，说清输入什么、发生什么、输出什么
   - 为什么长期成立：为什么它不随代码版本变，换个语言重写也用得上
4. **横向对比**：与对比语料中至少一家对比。**只写你亲自核对过源码的部分**，没核对过就不写，宁可少一张卡
5. **课堂练习**：1 道，让读者动手推演
6. **Takeaway**：三句话以内的硬结论

## 4. 交互演示规范（页面的灵魂）

**评判标准：一个不看代码的产品经理玩完演示，能把机制讲给别人听。**

- 原生 HTML/CSS/JS 内联，禁止外部库与 CDN
- 白底或米白底，禁止深色皮肤
- **每一步配一句人话字幕**，固定在演示区底部，跟随步进更新。说清这一步发生了什么、为什么
- **必须放「逻辑轨迹面板」**：一行一句白话步骤，右侧小字标真实文件与行号，随动画同步高亮当前行。行号必须实读源码核实
- 演示区**不贴源码原文和配置原文**，用图形和字幕讲逻辑
- 提供「播放 / 单步 / 重置」按钮，内联 SVG 图标加文字，触控目标 ≥44px，进入视野自动播放一次
- 有对比价值的做双栏对照，同一输入同时播放
- **鼓励给一个可切换的参数**，让读者自己发现边界条件
- demo 容器给唯一 id，移动端单列、可点、不依赖 hover
- 输入框若支持回车触发，必须判断 `e.isComposing`
- **各页演示不许撞车**。每页演示的是本章独有的那件事

### 演示方向分配表

并行生产前，先把每一章的演示方向写成一张表，一行一章，句式统一为「一个 X 怎么样：看它在哪里被 Y」。

这张表是防撞车的唯一手段。没有它，三十个子 Agent 会做出十个「一条命令穿过几道关卡」。

| 章节 | 演示的那件事 |
|---|---|
| NN <标题> | <一个 X 怎么样：看它在哪里被 Y> |

## 5. 源码引用红线（默认零代码）

- **默认每页 0 个源码面板**，机制全部用思路卡、白话和图讲
- 唯一例外：这段代码本身就是思想的最佳表达，短到一眼看完还能当金句。此时**最多 1 个面板、不超过 10 行**，先一句话说明它证明什么再贴
- 贴代码必须逐字粘贴，行号真实。**禁止为了让代码块短一点而悄悄删几行**
- 所有事实性论断都要能落到源码，落法是文中小字出处：`出处：<相对路径> 第 198 至 210 行`

理由：能在一页上贴的代码量远小于理解所需，贴一小段反而给人「看过了」的错觉。代码留在书稿里。

## 7. 交付前必须跑校验

```bash
python3.11 <CHECK_SCRIPT> <PAGE>          # 静态规则 + 渲染检查
python3.11 <VERIFY_SOURCES_SCRIPT>        # 出处的文件是否存在、行号是否越界
```

必须全绿才算交付。检查项至少包含：

- 页面骨架顺序、脚本顺序
- 主色变量是否挂在 `.lesson` 上
- 是否手写了应由构建注入的区块
- SVG 路径是否漏了 `fill="none"`
- 演示是否有播放/单步/重置、是否有字幕、是否有逻辑轨迹面板
- **反作弊：是否静态写死了动画完成态、是否用定时器强制显示**（真实发生过，子 Agent 为了让渐入检查通过而绕过动画）
- 文风禁忌正则扫描
