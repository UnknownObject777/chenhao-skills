## 1. 最高优先级铁律：零幻觉

违反此节的稿件直接作废。

1. **每一处源码引用、每一个行号、每一个类型名与函数名，动笔前必须用读文件工具实读核实。** 禁止凭印象写、禁止根据文件名推测、禁止根据大纲里的候选行号直接抄
2. 大纲里标 **✓** 的行号曾经核实过，**你仍然要自己读一遍确认**，因为你要引用的可能是相邻的行。没标 ✓ 的一律是候选位置
3. **代码块必须与源文件逐字节一致。** 保留原始缩进、属性宏、注释、空行。禁止转译、禁止美化、禁止删属性、禁止写「示意代码」或「简化版」
4. 找不到某机制的实现，**明确写出来**：`未找到对应实现，检索关键词为 X、Y、Z`。不许编一个看起来合理的实现
5. 源码里没明说、由你推断的结论，**必须显式标注为推断**
6. 引用注释原文时说明是注释，不要把注释内容当成代码行为陈述
7. 数字（行数、文件数、变体个数）必须实际统计过，统一用 `splitlines()` 口径
8. 引用符号链接时引真实文件，并注明链接关系

### 交付后会被机器校验

```bash
python3.11 <VERIFY_SCRIPT> --all        # 只报告
python3.11 <VERIFY_SCRIPT> --all --fix  # 顺带校正行号
```

它以内容为准、行号为辅：把引用块按省略标记切成连续段，要求每段在源文件里找到**完全连续**的逐字节匹配。任何一段拼不上就标 FABRICATION。

这意味着两件事：**行号写错会被自动纠正**，不必反复折腾；**静默删行一定会被抓到**。

真实案例：某章引用一段文档注释时悄悄删掉六行，删掉的恰好是「有意保留什么」那半段，导致正文结论不完整。

省略标记写成含 `...` 的整行注释，可带中文说明：

```
    // ... 填 SID 表 ...
```

**省略只用于确实无关的样板代码。** 曾有一章出现 25 处省略、参照章 0 处，校验器会统计省略密度并告警。

### 引用格式

行内提到文件用反引号：`<相对路径示例>`。

代码块三个组成部分都必填，**开头三反引号前必须空一行，且不能缩进**：

````
```153:160:<相对仓库根的路径>
<逐字节原文>
```
````

路径写相对仓库根的路径。引用对比语料时同样格式，路径以对比仓库为根。

## 2. 章节正文结构（八段，顺序固定）

### ① 场景还原

从一个具体的、会让读者点头的场景开局。不要从「众所周知」或概念定义开局。给一个真实会翻车的情形，或一个用户会遇到的具体困惑。三到五段，200 到 400 字。

### ② 逐行精读

本章主体，篇幅最大。按调用链或数据流顺序带读源码。每贴一段代码，前面用一到两句说明「接下来这段要证明什么」，后面用白话讲清「输入什么、发生了什么、输出什么」。

不要一次贴一大坨然后统一解释。一段代码一段话，交替推进。

### ③ 设计决策分析

回答「为什么这样做」。有评审红线条款、README 段落或模块头注释支撑的引原文；没有的从代码结构反推并标注为推断。这一段要给出「不这样做会出什么事」的具体后果。

### ④ 边界条件剖析

≥ 2 个「如果…会怎样」的追问，每个答案必须落到源码里确切的分支和行号。**不许用「取决于配置」这类含糊回答敷衍。**

### ⑤ 横向对比（双侧源码）

≥ 1 组对比，两侧都要给路径加行号。你负责那一章的对比对象见大纲。

对比要落到「同一个问题的两种答案」，并给出各自的代价。**禁止只说 A 有 B 没有**，要说清 B 为什么可以没有、或者 B 用什么别的东西补上了。

某一侧确实没有对应实现时，按铁律第 4 条写明检索关键词。

### ⑥ 互动演示设计

不写 HTML，写一份演示设计说明，给后续做课页的人用。必须包含：

- 演示要让读者明白的一句话结论
- 舞台上有哪些元素，用生活化比喻降门槛
- 分几步、每步的动画表现
- 每步配的一句人话字幕，直接写出文案
- 读者能操作什么
- 逻辑轨迹面板的伪代码行，一行一句白话，右侧标真实行号，随动画步进高亮
- 如果是对比沙盘，说明左右两侧各放什么、切换开关如何工作

形态三选一，见大纲指定：模拟器 / 决策沙盘 / 格式实验台。

### ⑦ 可迁移结论

站在「如果我自己做」的立场，明确三件事：哪些设计值得抄、抄的最小成本形态是什么、哪些是这个体量和威胁模型下才需要的过度设计。

**硬性要求：至少有一条结论不依赖 <主教材语言>**，并给出最小形态大概长什么样。

### ⑧ 思考题

≥ 3 道。至少 1 道要求读者改代码或改配置去验证，给出具体验证方法（改哪个文件、跑什么命令、观察什么现象）。

## 3. 深度承诺硬指标（交付前逐项打勾）

| 规范性材料精读 | ≥ 1 处全文精读并转述其约束意图 |
| 双侧源码对比 | ≥ 1 组，两侧都给路径行号 |
| 图 | ≥ 3 张，其中 ≥ 1 张时序图或状态图 |
| 边界条件追问 | ≥ 2 个，答案落到源码分支行号 |

**字数是下限不是目标。** 不够就再往源码里挖一层，不要靠省略代码块来压缩。

### 图的语法注意

- 时序图的 `loop` / `alt` / `else` 标签不要含中文标点，块名不要用中文

- 参与者别名不能含空格
- 节点文字换行用 `\n`
- 每张图前面用一句话说明这张图要回答什么

## 4. 文风（硬性执行，逐条过）

写给聪明但没读过源码的人。讲逻辑，少堆术语。先给结论再给证据。

### 硬性句式禁忌（交付前逐个搜索确认）

1. 省略号只用一半 `…`，不用 `……`
2. 禁止用 `——`，改成逗号、句号或拆句
3. 引号只在直接引用原话时保留，强调性引号一律去掉。引号用中文 `「」`
4. 禁止「不是…而是…」句式
5. 禁止「而不是…」收尾
6. 禁止评价式转述（「很简单」「非常巧妙」）
7. 禁止网文式情绪词（「震撼」「细思极恐」）
8. 禁止解读前置（「这背后其实有一个深层判断」），直接说判断本身
9. 标题不煽情，用概念词或动作词
10. 禁止段落分割线 `---`（只在八段之间用二级标题分隔）
11. 禁止「你品品」这类催感悟句式
12. 禁止「我一直觉得」这类自我感悟式过渡

上面这十二条都是能写成正则、交付前自动扫的。**不要用同义替换绕过正则**，比如把「而不是」换成「而非」。禁的是靠否定来制造对比这件事，不是那三个字。改法是正向陈述。

扫描时跳过代码块、行内代码和「」直接引用，否则源码字符和引用禁忌本身的地方会被误判。

下一节的表达偏好由人判断，不卡交付。

### 过程性语言：正文里不能有生产过程的痕迹

读者没见过大纲、没见过这份规范、不知道你是被派来写这一章的。所以正文里禁止过程性语言：

- 禁止「大纲写…」「和大纲不符」。要表达同一个意思，写成「一个流传很广的说法是…，实际检索下来…」
- 禁止「按铁律第 N 条」「按规范要求」「本次任务」「我负责的这一章」
- 禁止出现本机绝对路径，路径一律相对仓库根
- 检索无果的结论照样要写，但写成读者能用的形式：检索了哪些词、结论是什么、后续怎么复查

与大纲不符的地方**写进你最后回复给我的消息里**，正文只留经过核实的结论。

报「大纲写错了」必须带证据，格式是：**被质疑的原话 → 源码文件与行号 → 那几行的原文 → 为什么对不上**。三条经验教训：

- **引用区间含文档注释、或末尾没收进 `}`，都不算错。** 「函数本体从 172 行起，大纲却标 164」这种不要报
- **顺着继承和别名再查一层再下结论。** 曾有人报「这几行里没有 `UNKNOWN_TOOL`」，实际是那行抛的异常在类定义处就带着 `code: 'UNKNOWN_TOOL'`
- **约数按约数判。** 文件 298 行，原文写「约 300 行」，成立

### 表达偏好

- 删冗余：渲染情绪的修饰、套话一律删
- 去转述提示词：不写「它做了一个设计：」，直接进内容
- 口语化、松弛，允许中英混用（<列出保留英文原词的术语>）
- 段落间用「然后」「还有」「所以」「只是」衔接
- 长段拆短，一段只讲一个意思
- 措辞克制，「致命」「完全」这类强化词能不用就不用
- 并列内容直接列 1、2、3，列完再展开
- 类比要具体接地气
- 数据直接平铺，不加情绪铺垫
- 结论段不升华，直接给行动建议或硬结论
- 术语首次出现给一句白话解释

### 安全类内容的表述纪律

<如果本课涉及安全机制则保留本节>

- 区分「隔离措施」与「安全边界」。源码自己坦承的局限要照搬，不要替它吹
- 不写「无法绕过」「绝对安全」。写「这道防线挡住了 X，挡不住 Y，Y 由下一层负责」
- 举攻击例子一律用无害样例，不给可直接复用的恶意载荷
- 涉及已知绕过的，只讲机制不讲复现步骤

### 不把语言当卖点

读者不关心它是 <语言>，关心这个判断对不对。语言只在解释「为什么这个设计在这里成立」时出现。标题、开头、可迁移结论里不要把语言当卖点。

## 8. 常见失败模式（写作时自我提醒）

1. **贴了一大段代码但没解释它证明什么**：每段代码前后都要有话
2. **边界条件答成「看情况」**：必须落到源码分支
3. **对比写成功能清单对照**：要写两种答案各自的代价
4. **演示设计写成一句「做个动画演示这个流程」**：必须分步、必须有字幕文案
5. **可迁移结论全都依赖 <语言>**：至少一条要能用别的语言落地
6. **行号是猜的**：作废级错误
7. **把大纲里的候选行号直接抄进正文**：必须自己实读核实
8. **字数不够**：深度不够就再往源码里挖一层
9. **为了让代码块短一点而悄悄删几行**：必须写省略标记，机器校验会抓
10. **抄错一个标识符或一个符号**：真实案例：`SIGSYS_CODE` 抄成 `SIGSYS`、`unsafe { f() };` 抄成 `unsafe { f(); }`、漏掉 `#[test]`。贴代码一律复制粘贴，不要手打
11. **删引用让校验变绿**：真实案例：初稿 56 处引用带报错，交付时只剩 22 处全绿。校验器已加引用密度下限
